# Objective: Implement the panel's suggestions from the mock defense

## Goal
Update the system to address the panelists' suggestions from the mock defense. Explore the existing system first, so each change fits how the system works now.

## Constraints
- Explore the system before making changes.

## Context
- The suggestions come from the panelists after the mock defense.
- The system already has a decision support module, an admin applicant review flow with a checklist, a free trial for gym owners, and an "Add Customer" action.

## Tasks

### Exploration
- Explore the current system to understand its features and flows.

### Registration and onboarding
- Split the name field at registration into first name, middle name, surname and an optional suffix.
- Fill in the user's location automatically.
- Revise the age limit that requires a guardian.
- Add a separate login page for walk-in applications, and support walk-in members.
- Require a medical clearance.
- Add a waiver for members.

### Document review (admin)
- Add OCR (text reading from images) to submitted documents, so the system fills in the expiry date automatically.
- Review submitted files automatically. Ask the user to upload the file again if it is blurry. Reject it if its details do not match.
- Disable the "Passed" and "Failed" actions until the admin has viewed the documents.
- Hide the approval checklist and show it in a pop-up instead. The admin views the documents first, then completes the checklist to approve or reject.
- Notify the admin whenever a new applicant registers.

### Gyms and services
- Show gyms and their services as a catalogue, like a marketplace. Members should see pictures of a gym before they apply to join it.
- Let gyms add policies as document files.
- Show a free trial notice at the top of the screen when an owner logs in, so owners know they are on the free trial before they set up their gym.

### Staff hiring
- Add job postings.
- Add staff applications that collect credentials, a valid ID and work experience, so owners can check whether the applicant is qualified.

### Decision support
- Rename "Decision Support" to "Analytics".
- Add sparring matchmaking based on weight, height, rank or skill level, experience, and win/loss record.
- Add more decision support for gym owners: suggestions and automatic decisions, not only analytics.

### Labels
- Rename "Add Customer" to "Add Member".

## Open Questions
- Auto-fetch location: whose location (member, owner or gym), and on which screen?
- Guardian requirement: what is the new age limit?
- OCR and automatic review: which documents does this cover? What should the system compare the details against to decide they "don't match"?
- Medical clearance: who submits it (members, staff or both), and when is it required?
- Walk-in: what can a walk-in applicant do, and how is it different from normal member sign-up?
- Policies: who uploads them (owner or admin), and who must read or accept them?
- Job postings and staff applications: are these one flow (apply to a posting) or two separate features?
- "Automatic decisions" for owners: which decisions should the system make, and does the owner confirm them first?
- Sparring matchmaking: the notes list "rank" in one place and "skill level" and "experience" in another. Are these the same thing?
