# Packet 7D: Live delivery (R-83)

**Goal:** When a notice is created, anyone with the screen open sees it within seconds without refreshing. Booking changes and places left also update live.

## Dependencies

Packets 7.0, 7A and 7B. The notification provider and polling hook were built in 7.0.

## Decisions

- Polling only. No websockets, SSE, broadcasting or push.
- Poll interval is 15 seconds for notices and session/booking screens.
- Polling pauses while the tab is hidden and refreshes as soon as it becomes visible or focused.
- A poll must not flash the loading skeleton. Only the first load shows skeletons.
- The unread count comes from the shared provider; pages do not fetch it themselves.

## Frontend tasks

### Shared behaviour

- [x] Confirm `usePolling` runs immediately, repeats on the interval, pauses when hidden, refreshes on focus/visibility, and never overlaps.
- [x] Each polled page separates “first load” from “silent refresh”:
  - first load: `data === null`, show skeletons.
  - silent refresh: keep the current data on screen; replace it when the response arrives.
  - poll errors: keep the current data and do not show a toast; the normal load error state stays for the first load.

- [x] `frontend/src/pages/member/SessionDetails.tsx`: poll `GET /gyms/{gymId}/timetable/{sessionId}` every 15 seconds. Places left must change without a reload. A cancelled session must switch to the cancelled state.

### Shared polling rules

- [x] All callbacks passed to `usePolling` are stable (`useCallback`) and depend only on the values that identify the request.
- [x] Changing a filter, page or date still triggers a normal load immediately.
- [x] Do not poll when the user is signed out.
